# Laser Pro Studio — المواصفات المعتمدة للإصدار 1.0

**الحالة:** مواصفات مشروع، وليست ميزات منفّذة كلها. أي ميزة لا تعتبر جاهزة إلا بعد الاختبار على Windows وAndroid.

## الأساس التقني
- تطبيق واحد بكود Flutter ونسختين Windows وAndroid، وليس HTML.
- حساب مستخدم واحد وبيانات موحّدة، مزامنة ثنائية الاتجاه عبر خدمة مُدارة مثل Supabase مع صلاحيات وقواعد وصول آمنة.
- بيانات محلية للحالات دون إنترنت + طابور عمليات قابل لإعادة الإرسال، وحل التعارضات، ومعرّفات تمنع الازدواج.
- نسخ احتياطية واسترجاع واختبار التحديث قبل الاعتماد، والتحديثات سهلة قدر الإمكان.
- عدم البدء بإدخال بيانات عمل حقيقية في نسخة محلية غير متزامنة.

## الواجهة
- أسود/ذهبي هو التصميم الافتراضي الثاني المختار، فخم لكن قليل الأزرار.
- الثيمات الأربعة مختلفة فعلياً في الهيكل الخارجي والأشكال والخطوط والألوان (الملكي، اللؤلؤي، الأزرق، الخشبي)، مع ثبات وظائف وحقول كل نموذج.
- الرئيسية فيها طلب جديد ومساعد اليوم؛ القائمة الأساسية: طلباتي، منتجاتي، استوديو الملفات، المخزون، الحسابات، مشترياتي السابقة. الإعدادات من قائمة الحساب، وسجل الزبائن مرتبط بالطلبات والبحث.
- كل زر وظيفة محددة دون تكرار أو تزاحم.

## الطلبات والزبائن
- الطلب يختار الزبون عبر رقم هاتفه الموحّد، ثم المنتج، مع اسم العميل/رقمه/عنوانه/ملاحظاته وتاريخ طلباته.
- بحث عن رقم واتساب دون حفظه في جهات الاتصال. **لا تعتمد ميزة قراءة إشعارات واتساب أو التعرف التلقائي على المرسل** دون تكامل رسمي منفصل.
- لكل طلب زر فتح واحد يعرض كل البيانات، الصور، SVG، مواصفات، موعد وتسليم ودفعات وتكلفة وربح.
- سعر مرجعي واحد لكل منتج قابل للتعديل على الطلب فقط، مع حفظ لقطة سعر البيع وتكلفة المواد لكل طلب قديم.
- عمليات متعددة لتسجيل قبض مع المبلغ/طريقة القبض/التاريخ، وحساب الباقي. سجل التسليم منفصل عن سجل الدفع.
- إمكانية إعادة الطلب من نفس مواصفات زبون سابق دون تعديل تاريخ الطلب القديم.

## المنتجات والملفات
- منتجاتي: اسم وتصنيف، عدة صور، وصف، القياسات والخامات والسماكات والخيارات، سعر مرجعي، وصفة المواد، روابط SVG والملفات.
- استوديو الملفات: إنشاء مجلدات بتسمية حرة؛ حفظ تصميم SVG وصور معاينة ومصدره وتصنيفه وكلمات بحث وملاحظاته؛ كشف التكرار بحسب بصمة الملف.
- ربط الملف بالمنتج وبالطلب دون نسخ غير ضروري.

## المخزون وحساب التكلفة
- تعريف مواد الخشب والأكريليك والتغليف واللاصق والإكسسوارات مع بيانات الوحدة والعبوة والقياسات والكمية والسعر.
- المستخدم يختار **المادة والكمية/المساحة/الطول المستخدم**، لا يدخل «تكلفة مواد» بالدولار يدوياً في الطلب.
- حساب تكلفة كل بند تلقائياً، تقدير تكلفة كهرباء تشغيل الليزر بالدقائق وقدرته وتعرفة الكهرباء القابلة للتعديل.
- قيم مرجعية أولية قابلة للتعديل: تعرفة 0.90$/kWh، قدرة الليزر التقديرية 216W. بلا حساب أجرة ساعة العمل أو قسم مصاريف تشغيل منفصل.
- حساب الربح المتوقع والفعلي وتفصيل المواد والتغليف والكهرباء. الاستهلاك الفعلي للمخزون يُثبّت مرة واحدة فقط عند تأكيده، مع عملية عكس عند التعديل/الإلغاء.
- حفظ أسعار تاريخية وعدم إعادة كتابة تكاليف الطلبات السابقة عند تغيير سعر مادة.
- المبالغ والأرباح عبارة عن صافي مساهمة الطلب بعد التكاليف المباشرة، وليست أرباحاً محاسبية شاملة.

## الحسابات ومساعد اليوم
- مؤشرات إجمالي مبيعات الطلبات، المقبوض، باقي القبض، تكلفة مباشرة، هامش الطلبات، تقارير المنتجات الأكثر ربحاً.
- تنبيهات طلب متأخر، تسليم قريب، دين زبون، مخزون ناقص.
- أولوية الدقة المالية، سجل تدقيق للتغييرات والمعاملات، عدم تسجيل قبض مكرر.

## مشترياتي السابقة — معزولة تماماً
- دفتر خاص للمقتنيات قبل تأسيس المشروع: الاسم/تاريخ الشراء/السعر/المورد/الصورة أو الفاتورة/الملاحظات.
- هذا دفتر تذكيري، لا يؤثر على المخزون أو تكلفة الطلب أو الربح أو الحسابات أو تقارير الأعمال **نهائياً**.

## الإعدادات
- ثيم وتخطيط وأحجام خط؛ الأسعار والوحدات وتعرفة الكهرباء وأهداف الربح؛ خيارات القبض والتسليم والعملة؛ إعدادات الفواتير؛ النسخ الاحتياطية؛ حالة المزامنة؛ التحديثات.
- الخيارات الموجودة تغير من داخل التطبيق بلا تعديل Dart. الوظائف البرمجية الجديدة تتطلب نسخة تطبيق جديدة.

## تسليم النسخة النهائية
- لا يُقال «جاهز» إلا باختبارات Android وWindows، المزامنة باتجاهين، انقطاع الشبكة والتعافي، منع التكرار، تحميّل الملفات، النسخ الاحتياطي والتحديث الآمن.
- مشروع GitHub الحالي يضم نموذجاً أولياً للحسابات والمخزون والطلبات فقط، بلا مزامنة؛ APK الحالي إن بُني هو **للتجربة لا للإنتاج**.
